# Austin Education — 学生管理系统

take-home 题目所述系统的垂直切片：
**预约试听 → 试听发生 → 顾问被追着去转化 → 家庭购买课时 → 老师记录出勤 → 课时结算 →
在课时用完之前预警。**

Part A 是 [`DESIGN.md`](./DESIGN.md)。配套文档在 [`docs/`](./docs)：
PRD、架构文档、UI/UX、OpenAPI 契约，以及 11 篇 ADR。

---

## 1. 怎么跑起来

### 环境要求

| 东西 | 版本 | 为什么 |
|---|---|---|
| Go | 1.26+ | `go.mod` 的目标版本是 1.26 |
| Node | 20.19+ | Vite 8 / React 19 |
| MySQL | **8.0.16 或更高** | schema 用了 `CHECK` 约束，MySQL 从 8.0.16 起才真正强制它 |

任何 MySQL 都行——本机、Docker、或托管实例。你**不需要**手工建库或跑任何 SQL：
服务端会自行创建缺失的数据库并应用自己的迁移。

### 1.1 配置

复制示例文件并填入你自己的值：

```bash
cp .env.example .env
```

```dotenv
PORT=8080
DB_DSN="user:password@tcp(127.0.0.1:3306)/student_management?charset=utf8mb4&parseTime=true&loc=Australia%2FMelbourne"
JWT_SECRET=any-random-string
DEEPSEEK_API_KEY=sk-...          # 可选；没有它 AI 卡会降级，但什么都不会坏
```

`loc=Australia%2FMelbourne` 这一段是有承重作用的，不是装饰——见 §4。

`.env` 已在 gitignore 中。本仓库没有提交任何凭据。

### 1.2 建表并载入演示数据

```bash
cd backend
go mod download
go run ./cmd/server -migrate     # 建库 + 应用迁移
go run ./cmd/server -seed        # 载入演示数据
```

`-seed` 是破坏性的：它会清空业务表并重建。可以安全重复执行，并且会打印它保证生成的状态：

```
正在写入演示数据 ...
演示数据写入完成
  admin：3，演示登录 mei.lin / demo1234
  老师：4，演示登录 zhou.ya / demo1234
  家庭：演示登录 parent.zhao / demo1234（Zhao, Nina）
  学生：37
  班级：8
  课次：40
  演示状态：4 条跟进已逾期，6 场试听待进行，5 名学生课时不足，今日 1 节课
```

几点说明：

- `admin` / `老师` 的数字是**写死的**（各 3 个、4 个演示账号）；`学生` / `班级` / `课次` 是**实际写入的行数**。
- **`演示状态` 那一行会随运行日期变化**：它统计的是「此刻」有多少条跟进已逾期、多少场试听还没开始、
  多少名学生课时不足、今天有几节课。上面的数字来自一次实际运行。
- 这行**故意不做列对齐**：`%-8s` 按**字节**补齐，而一个中文字符在终端里占**两列**，所以一旦按列对齐，
  中文字段之后的每一行都会整体错位。改成 `标签：值` 就没有可漂移的东西。

任何一个队列为空时，seed 会以非 0 退出，而不是报告成功——演示时一块空的看板和一个坏掉的
查询在观感上无法区分，所以它选择大声失败。

### 1.3 启动

```bash
# 终端 1 —— API 监听 :8080
cd backend && go run ./cmd/server

# 终端 2 —— UI 监听 :5173
cd frontend && npm install && npm run dev
```

打开 <http://localhost:5173>，用下面任意一个账号登录：

| 角色 | 用户名 | 密码 | 落地页 |
|---|---|---|---|
| admin / 顾问 | `mei.lin` | `demo1234` | `/today` —— 工作台 |
| 老师 | `zhou.ya` | `demo1234` | `/teach/today` —— 今日课程 |
| 家长 / 学生 | `parent.zhao` | `demo1234` | `/me` —— 家庭课时账本 |

`mei.lin` 名下持有 37 名学生中的 13 名，也是三条队列的种子数据所针对的账号。

## 2. 试着把它弄坏（这才是重点）

每条业务规则都在**服务端**强制。UI 只反映状态，所以验证规则的正确方式是**完全绕过 UI**。

API **刻意接受两种凭据通道**：给浏览器用的 `httpOnly` Cookie，和给 `curl` 用的
`Authorization: Bearer`。后者存在的意义，就是让评审者不打开浏览器也能证明规则成立。

```bash
API=http://localhost:8080/api/v1
TOKEN=$(curl -s -X POST $API/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"mei.lin","password":"demo1234"}' | python -c 'import sys,json;print(json.load(sys.stdin)["data"]["token"])')
```

然后逐条试。**预期中的失败就是产品本身。**

| # | 尝试 | 预期 |
|---|---|---|
| R1 | 为一个已经试听过该科目的学生 `POST /trials` | `409` `40905` |
| R3 | `POST /classes/:id/enrollments` 到一个与该生已报班级周时间槽重叠的班 | `409` `40901` |
| R3 | `POST /classes/:id/enrollments` 到一个已满的班 | `409` `40902` |
| R6 | 为一个 `balance <= 0` 的学生 `POST /classes/:id/enrollments` | `409` `40904` |
| R4 | 为同一个学生对同一节课 `POST /lessons/:id/attendance` **两次** | 第二次是空操作；账本不会再动 |
| R7 | 对一个属于其他 admin 的学生 `PATCH /students/:id` | `403` `40301` |
| R10 | 取消一段包含已完成课程的区间 | `409`；已完成的课永远不会被取消 |

**R7 值得认真试**，因为“全读 / 只写自己”正是这个切片实现的权限层：用 `mei.lin` 登录，
`GET /students` 返回整个中心，`GET /students/:id` 对任何学生都能取——但 `can_write`
对不属于她的人全是 `false`，并且写接口无论客户端发什么都会返回 `403`。

**R4/R5 也值得认真试。** 课时是一本只增不改的账本；余额是 `SUM(delta)`，从不落库。
重放一次结算不会重复扣费，因为 `UNIQUE(student_id, lesson_id, reason)` 会拒绝第二次写入，
而服务端把它当成成功而不是错误。

## 3. LLM 那处功能

它被放在“最能替人省事”的位置，而不是“演示效果最好看”的位置。

**放在哪：** 试听之后，顾问必须决定怎么把这家人谈下来；而当余额变低时，必须有人决定
怎么开口要这次续费。这正是题目自带场景点名的两个漏钱时刻。所以：

- `POST /api/v1/ai/trial-conversion/:student_id` → 转化卡：信号强度、家长的顾虑、
  卡点、下一步动作。
- `POST /api/v1/ai/renewal-risk/:student_id` → 流失风险卡：风险等级、风险因素、
  推荐的课时包、建议联系的时间窗。

**结构化输出，服务端校验（R8）。** 要求模型返回固定的 JSON 形状。然后**不信任**这个响应：
每一个枚举取值的字段都要过白名单，才允许落库或返回。一张 `churn_risk` 不在允许取值内的卡，
会被当作**非法输出**处理，而不是当作数据。

**降级是设计好的路径，不是事后补丁。** 每张卡自带来源：

| `ai_status` | `source` | UI 显示什么 |
|---|---|---|
| `ok` | `llm` | 模型给的卡 |
| `invalid` | `rule` | 模型答得不符合契约；改用确定性的规则卡 |
| `unavailable` | `rule` | 模型调不通；同一张规则卡 |

所以工作流永远不会被模型卡住。想自己看降级：把 `DEEPSEEK_API_KEY` 去掉（或把
`DEEPSEEK_BASE_URL` 指到一个不可达地址），重启，然后请求一张卡——你会拿到 `rule` 来源的卡，
和一个照常可用的界面。这是这个功能最重要的性质：**模型挂了，你损失的只是精致度，
不是干活的能力。**

规则兜底不是占位桩。它从同样的事实（余额、试听结果、跟进时长、历史出勤）推出同样的字段——
这也是它为什么是一份可信的答案，而不是一个占位符。

## 4. 架构

```
backend/
  cmd/server/         入口：-migrate / -seed / 服务
  internal/handler/   HTTP：参数绑定、鉴权、统一响应信封
  internal/service/   业务规则、事务、课时账本
  internal/repo/      连接、数据库引导
  internal/clock/     “当前时间”的唯一来源（见下文）
  internal/seed/      演示数据，包含刻意构造的边界状态
  migrations/         版本化 SQL
frontend/
  src/lib/            API 客户端、类型（镜像 Go struct）、鉴权上下文
  src/shell/          应用外壳、按角色裁剪的导航
  src/pages/          一块屏幕一个文件
  src/components/     表现层组件
docs/                 PRD、架构、UI/UX、openapi.yaml、decisions/ADR-*.md
```

分层是严格的：`handler → service → repo`，依赖永远只向下。没有 handler 里藏着业务规则，
也没有 service 写 HTTP。

**时钟是一块刻意设计的基础设施。** 业务时区是 `Australia/Melbourne`，但 MySQL 实例跑在
`CST`。把两者混用，会因夏令时把每个时间戳静默挪走 2 或 4 小时。所以 SQL 从不调用 `NOW()`、
`CURDATE()` 或 `CURRENT_TIMESTAMP`；所有业务时间都经 `internal/clock` 从 Go 侧下发，
列类型用 `DATETIME(3)` 而不是 `TIMESTAMP`，数据库因此不会在我们背后做任何转换。
见 [ADR-007](./docs/decisions/ADR-007-timezone-melbourne.md)。

## 5. 刻意没做的部分

这是一个切片，所以有几样东西是故意缺席的。每一条的原因都写在
[`DESIGN.md`](./DESIGN.md) §2，简版如下：

- **没有家长专属界面。** 家长和学生共用一个凭据；家庭视图就是学生视图。做两套只会把界面
  面积翻倍，却不会改变任何一条规则。
- **没有出勤 / 课时 / 请假 / 角色的 CRUD 页。** 每张表不配拥有自己的一块屏幕。
  点名活在它所属的那节课里。
- **请假没有审批流。** 它按 24 小时阈值即时判定。加一个人工审批步骤会造出一个定义不清的
  “待审批”状态，而且挡不住任何人直接来上课。
- **课时包过期只是字段，不做强制**（R9）——题目没说课时包过期时应该发生什么。

已知缺口，如实写出而不是藏起来：

- 前端没有测试。后端的规则靠直接调 API 验证，演示时也是这么验（§2）。
- `docs/openapi.yaml` 里的契约是对着实现**核对**出来的，不是从实现**生成**的；
  这中间的漂移与解决过程记在
  [ADR-011](./docs/decisions/ADR-011-contract-drift-reconciliation.md)。
- [`docs/decisions/OPEN-DECISIONS.md`](./docs/decisions/OPEN-DECISIONS.md) 里还有两个问题
  没有关闭，主要是 48 小时跟进 SLA 是否计入周末。目前按自然小时处理，阈值是可配置常量。
- **排课页读的是一整个窗口，不是全部分页。** “待排课”集合和班级名单的学生选择器都在单个
  窗口里请求 `limit=100`（服务端上限 200）。对学生数超过 100 的机构，这个窗口会
  **静默地只覆盖前 100 名**——窗口内完整，窗口外未知。它没有做分页，因为这块屏幕需要全集
  才能算出补集。按题目给定的规模（10 名顾问、每人约 100 名学生），这是一个真实的瓶颈，
  我把它写下来，而不是用一个对着种子数据 37 人永远触发不了的分页控件去糊上。

## 6. AI 工具用在了哪些环节，以及哪些建议我没采纳

题目要求写这一段，如实作答。

**AI 用在了哪里**

1. **先做需求拆解。** 题目是刻意模糊的，所以第一遍是把所有名词列出来、理清它们之间的关系
   ——有哪些实体，其中哪些其实是同一个东西戴了两顶帽子。`guardians`、`credit_packages`、
   `credit_ledger` 之所以是三张独立的表，而不是一个 `student.credits` 字段，就出在这一步。
2. **行业调研。** 澳洲的辅导中心实际怎么运转——试听作为销售工具、课时按包售卖、每周重复的班。
   这改变了模型：预付费才是生意，学生档案几乎是附属品。
3. **有规格说明书的大批量工作。** 规则和 schema 定下来之后，AI 写了大部分 handler 和
   repository 代码，以及前端表示层几乎全部。
4. **对抗式自审。** 追问“这个设计哪里有问题”，产出了“明确不做”清单里的大部分条目，
   以及 `DESIGN.md` §4 里那些关于强制边界的说明——尤其是 MySQL 无法像 Postgres 的
   `EXCLUDE USING gist` 那样表达重叠约束，所以报名做成了一条加锁事务。

**没采纳的 AI 建议**

- **用 `student.credits` 字段代替账本。** 更简单，而且是错的：一旦发生退款或调整，
  一个可变余额答不出“为什么是 3”。账本是只增的，余额是推导出来的，schema 本身就拒绝被
  原地编辑。见 [ADR-008](./docs/decisions/ADR-008-credit-ledger-append-only.md)。
- **单独建 `parents` 表、给它自己的登录，再加一张家长-学生关联表。** 否决：模型要为每次
  读取回答“这是谁的家长”，只为服务一个在这个切片里不改变任何规则的区分。
- **把余额存在学生行上，账本只当审计日志。** 那账本就变成对事实的描述，而不是事实本身，
  两者会漂移。理由同上。
- **“只能写自己的学生”这条规则只在前端强制。** 直接否决：一个被禁用的按钮不是权限。
  `can_write` 由服务端计算，写接口独立于它做拒绝。
- **一个通用的“AI 助手”聊天框。** 题目点名这是反模式，说得对：聊天框是把活推回给用户的地方，
  不是接走活的地方。这里的 LLM 在特定时刻产出特定产物。
- **校验失败时仍然把模型的输出放出去。** 诱人的捷径是“反正就这样展示吧”。否决：一份不符合
  契约的答案不是“降级答案”，而是“未经校验的答案”，所以它会被规则卡替换掉。

**读这个仓库时需要注意一件事：** git 历史没有 squash，所以它把过程连同纠正一起呈现。
有几个提交是对更早决策的修正——ADR-011 记录的契约漂移就是一例：已实现的 `/auth/me`
和文档里的那个曾经分叉，最后是逐字段对齐解决的，而不是把 spec 改写成迁就代码。
