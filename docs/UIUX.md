# Austin Education · 学生管理系统 UI/UX 设计方向

> 生成日期：Phase 1 | 设计师：颜好看 | 基于：take-home-student-management.html + 架构锁定（Vite + React + TypeScript）
> 定性：**预付费履约系统**（课时 = 家长已付的钱 + 库存 + 排期承诺）
> 三轴刻度：`DESIGN_VARIANCE = 3` / `MOTION_INTENSITY = 2` / `VISUAL_DENSITY = 7`
> 设计寄存器：**Product Register（产品型）** —— 内部运营控制台，一切服从扫读与任务完成，不做任何营销表达。

---

## 1. 需求定性（设计输入）

### 1.1 这不是什么

不是营销站、不是注册转化页、不是 C 端产品官网。
**没有任何 Hero 区块、没有 Landing section、没有宣传文案、没有注册 CTA。** 首屏必须是角色今天要处理的东西。

### 1.2 这是什么

一个 **课时履约控制台**。三个角色关心的都是同一件事的不同切面：**课时余额与进度状态**。

| 角色 | 一句话 Job-to-be-done | 最怕（= 设计要解决的第一痛点） |
|---|---|---|
| **admin**（课程顾问兼教务，10 人 × 100 学生） | 「今天我有哪些学生必须马上处理」 | 漏跟进试听、漏提醒续费 |
| **teacher**（20 人，周 60 节课） | 「今天几点上课、班里有谁、谁是新来的、谁请假了」 | 不知道今天班里谁是新来的、不知道谁请假了 |
| **student / 家长**（家庭账号） | 「我的课时还剩多少、怎么少的、怎么请假」 | 课时不明不白少了 |

### 1.3 设计对象不是表，是「状态」

评分表原话：*好的表现是"页面数量克制，每个角色打开就能看到自己最关心的信息；状态一眼能区分"；不好的是"把每张表做成一个 CRUD 页面"*。

所以本设计的第一原则是：**不为每张表开一个页面，而为每个角色开一个"今天就做这些"的页面**，列表/表格只是它的呈现方式。

## 2. 对标品牌与设计语言

### 2.1 联网调研结论（4 个参考）

| 参考 | 学到什么（本项目直接采纳） | 采纳的决策点 |
|---|---|---|
| **Linear** | ① 36px 行高、几乎无 chrome，"density without clutter"；② "Needs your attention" 分组置顶；③ 状态点不是纯色块，而是**同色不同形状**（hollow ring / dashed ring / partial ring / filled）；④ 极窄强调色，标题永远用中性深色 | admin 工作台的三分区结构、行高 36px、**出勤状态的形状编码**、透明度化边框代替阴影 |
| **Stripe Dashboard** | ① 涉及"钱"的数字给绝对量不给百分比；② KPI 卡上限 4 个，多了就是墙；③ 语义色被严格保留，不出现在装饰里 | 课时余额显示 **`12 / 40` 剩余/总量**而非百分比；老师端/工作台每屏 KPI ≤4 个 |
| **Height / Plane** | ① 任务卡片带富状态元数据，可在列表内就地推进而不跳转；② 无数据时给出下一步动作而非"暂无数据" | 所有列表行**行尾直接给动作按钮**，不跳页面；空态必须带 1 个 CTA |
| **Airtable / Notion 数据库视图** | 同一份数据用不同视图（表格/看板/日历）服务不同任务；视图持久化在 URL | admin 的学生列表提供「我的学生 / 低课时 / 待排班 / 全部」四个**同一数据源的 Saved View**，而不是四个页面 |

补充参考（上述多家 dashboard 研究的行业共识，本次已采纳）：侧边导航 240–280px、12 列栅格、卡片 1px 描边优于阴影、sticky 表头 + 列排序、密度可控。

### 2.2 设计语言命名

**「履约控制台 / Fulfillment Console」**

四条硬性表述：

1. **边框驱动，不用阴影分隔。** 所有层级用 `1px hairline` 表达；阴影只留给浮层（popover / dropdown / dialog），永不用于静态卡片。
2. **中性色占 90%，强调色克制。** 每屏强调色可见使用 ≤ 2 处。
3. **数字一律等宽。** 所有课时、金额、时间、学号使用 `font-variant-numeric: tabular-nums` + JetBrains Mono，保证扫读时列对齐。
4. **状态三通道冗余编码：颜色 + 形状/图标 + 文本。** 任何状态去色后仍可辨（见 §4）。

### 2.3 为什么这套适合"高密度、多状态、需要扫读"

- 运营后台用户是**每天用 8 小时的老手**，不是第一次打开的新手。他们要的是 predictability 和保密度，不是惊喜 —— 所以 `Variance = 3`（严格对称网格，零非对称布局）。
- 状态多且重叠（一个学生可以同时"试听未反馈"+"超期"+"低课时"），颜色一旦成为唯一载体就会互相淹没。Linear 的做法给了答案：**先把形状区分解耦，颜色只做 reinforcement**。
- Motion 压到 2：操作 feedback 150ms，面板进出 200ms，**没有任何装饰性动画、没有任何渐变、没有任何悬浮 ring 呼吸灯**。这不是保守，是让老师在点名时不分心。

## 3. 设计系统

### 3.1 三轴刻度（已标定）

| 维度 | 值 | 具体行为 |
|---|---|---|
| `DESIGN_VARIANCE` | **3**（可预测） | Flexbox + 严格 12 列对称网格，等距 padding，**无**负 margin 重叠、**无**非对称留白、**无**居中 Hero |
| `MOTION_INTENSITY` | **2**（几乎静态） | 仅 hover/active/focus 的 150ms 过渡 + 200ms 面板进出；**无**编排动画、**无**滚动揭示、**无**持续微动画 |
| `VISUAL_DENSITY` | **7**（偏驾驶舱） | 表格行高 36px（可选 32 紧凑 / 44 舒适）、**禁止**通用卡片容器包裹每组数据，用 `divide-y` hairline 分组；数字全部 tabular-nums |

> `Density` 提供三档切换（Density control 是 administrative table 的老手必需），并用 URL query 持久化，不用 localStorage（方便老师把"舒适模式"链接发给同事）。

### 3.2 配色（A1 Identity + A2 Semantic + B Slot）

主色选 **Petrol Blue `#0F5C73`**（石油蓝-深青），理由：
① 澳洲教育机构，海港意象，稳重可信；② 与"课时是钱"的财务属性匹配；③ **刻意避开 Indigo / Violet 系**，避免 AI 默认靛蓝 `#6366F1` 的套路感；④ 不与任何语义色（绿/琥珀/赤）抢车道。

```css
:root {
  /* ── A1 Identity ───────────────────────────── */
  --bg:              #F4F5F6;   /* 页面底 */
  --surface:         #FFFFFF;   /* 卡片 / 表格容器 */
  --surface-sunken:  #FBFCFC;   /* 表头 / zebra */
  --fg:              #1B1C1F;   /* 主文本      15.3:1 */
  --muted:           #6C6F78;   /* 次文本       5.0:1 */
  --accent:          #0F5C73;   /* 主强调       7.4:1 on #FFF */
  --border:          rgba(0,0,0,0.08);
  --font-display:    "Inter", "Noto Sans SC", -apple-system, sans-serif;
  --font-body:       "Inter", "Noto Sans SC", -apple-system, sans-serif;

  /* ── A2 Semantic ───────────────────────────── */
  --success:         #15803D;   /* 出勤 / 已跟进   4.6:1 */
  --success-bg:      #E8F3EC;
  --warn:            #B45309;   /* 低课时 / 迟到   5.1:1 */
  --warn-bg:         #FDF1E2;
  --danger:          #B91C1C;   /* 旷课 / 流失风险 6.0:1 */
  --danger-bg:       #FBECEC;
  --accent-hover:    #0C4A5C;
  --accent-active:   #093B4A;
  --accent-bg:       rgba(15,92,115,0.07);
  --accent-on:       #FFFFFF;   /* on --accent   6.9:1 */
  --font-mono:       "JetBrains Mono", "SF Mono", ui-monospace, monospace;

  /* ── B Slot 别名 ───────────────────────────── */
  --fg-2:            #37393E;
  --meta:            #9EA1A9;   /* ▲ 仅用于图标与 disabled，不得用于正文（2.6:1 不达标） */

  --neutral-bg:      #F1F3F5;

  /* ── C Extension（本项目专属） ─────────────── */
  --credit-track:    #DDE1E4;   /* 课时条轨道 */

  /* ── Focus & Motion ────────────────────────── */

```

**语义色分工（业务绑定，不可挪用）：**

| Token | 业务含义 | 唯一用途 |
|---|---|---|
| `--success` | 出勤正常、已跟进、课时充足 | 状态 badge、课时条填充 ≥20 节 |
| `--warn` | **低课时**、迟到、跟进走近 48h | 课时条 6–19 节、SLA 条 >24h |
| `--danger` | 旷课、**流失风险**、超期严重、课时透支 | 课时条 ≤5 节、超期 >48h |
| 中性 `--neutral-fg` | 待跟进、请假已准（不扣）、试听未反馈、AI 降级态 | 虚线 / 空心形状 badge |

> `--accent` 只做两件事：可点击的主操作按钮、导航当前项。**标题、正文、成功/警告状态一律不用强调色。**

### 3.3 字体

```
Display / Body : Inter + Noto Sans SC（回退 PingFang SC / Microsoft YaHei）
Mono           : JetBrains Mono（课时、金额、时间、日期、学号）
```

> Inter 在此处是**功能性选择**（字宽窄、OpenType feature 完整、中英混排基线稳），不是"高级感宣称" —— UI 里不存在任何大字号展示标题字体。与源HTML 的 `Noto Sans SC` 保持一致。

| 层级 | 字号 / 行高 | 字重 | 字距 | 用途 |
|---|---|---|---|---|
| h-page | 20 / 28 | 590 | -0.01em | 页面标题 |
| h-section | 13 / 18 | 590 | 0 | 分区标题（表格不用衬线也不用 caps 滥用） |
| th | 11 / 16 | 510 | **+0.04em**, ALL CAPS 时 +0.06em | 表头（仅英文表头用 caps） |
| row-title | 13.5 / 20 | 510 | 0 | 表格主文本 |
| body | 14 / 22 | 400 | 0 | 正文、抽屉说明 |
| meta | 12 / 16 | 400 | 0 | 时间戳、次要列 |
| badge | 12 / 16 | 510 | 0 | 状态胶囊 |
| mono-num | 13.5 | 400–590 | 0 | `tabular-nums` 课时/金额 |

**字重只三级：400 / 510 / 590。** 中文文案不用斜体（Noto Sans SC 无真正 italic）。

### 3.4 间距 / 圆角 / 阴影

- **间距**：4px 网格 —— `4 / 8 / 12 / 16 / 20 / 24 / 32 / 48`。禁止 5/7/13/15/22/30。
- **圆角**（后台上限 8px，禁止 12+ 的过度圆滑）：`--radius-sm: 4`（badge/tag）· `--radius-md: 6`（按钮/输入框）· `--radius-lg: 8`（卡片/面板/弹窗）。不用 pill 除头像。
- **阴影**：仅浮层 `--shadow-popover: 0 1px 2px rgba(0,0,0,.04), 0 4px 12px rgba(0,0,0,.08), 0 0 0 1px rgba(0,0,0,.06)`。静态卡片零阴影。
- **z-index**：`base 0 / sticky-header 100 / dropdown 1000 / drawer 1100 / modal 1200 / toast 1300`。

### 3.5 栅格与密度

- 侧栏 **240px**（可折叠到 64px 图标栏）；顶栏 **44px**；内容区 12 列 / gap 16px；最大宽度 **1440px**（不留 container-max 限制，后台吃满宽度）。
- 表格行高默认 **36px**；紧凑 **32px**；舒适 **44px**（移动/触屏强制 44）。
- 表格：表头 sticky、首列 sticky（学生名），支持排序，`hover` 行 --row-hover。

## 4. 状态可视化规范（本 Phase 重点）

### 4.0 总原则：三通道冗余编码

> **任何状态必须同时具备：① 颜色 ② 形状或图标 ③ 文本。** 去掉任意一个，剩下两个仍能表达。验收方法：把界面截图**转灰度**，如果状态仍可读，才算通过。

反面因此成立：**禁止只用一个彩色圆点表示状态**。这是本项目 UI 的一票否决项。

### 4.1 课时余额（连续量 → 数字 + 条 + 阈值动作）

课时不是布尔值，是**下降中的库存**。所以不能用 badge，必须用「进度条 + 绝对数字 + 阈值触发动作」三件套。

组件 `CreditCell`：

```
  课时条   48×6px / radius 3px / track var(--credit-track)
  数字     "12 / 40"  mono tabular-nums，剩余数 590 字重，总量 muted
  分档     ≥20        fill var(--success)  无任何附加标记
           11–19      fill var(--warn)
           6–10       fill var(--warn) + 12px triangle-alert + 数字 590
           ≤5         fill var(--danger) + triangle-alert + 行尾出现 [催续费] 按钮
           ≤0 透支    fill var(--danger) + **虚线 track** + 文本 "已欠 2 节"
```

关键：
- **必须显示 `剩余 / 总量`**，不能只显示百分比 —— 家长投诉的核心是"不知道少了多少"，运营核对也一样。
- **≤5 节时状态表现为「一个按钮出现」而非「一个颜色变化」** —— 这是"状态驱动动作"，也是--and-growing 评分表所说的"每个角色打开就看到最该做的"。
- 灰度验收：≤10 档靠「加粗数字 + 三角图标 + 出现按钮」三件事，去色后完全可读。

> **`--accent` 不参与课时表达。** 课时只用语义色，因为它是"钱"，钱的红黄绿语义必须独占。

### 4.2 出勤状态（6 值枚举 → 形状优先）

这是老师端的核心。**Linear 的状态点给了启发：同色不同形。** 本项目进一步：**不同形状 + 不同图标 + 不同填充方式**，并保证灰度可辨。

| 状态 | 图标（Lucide 16px） | 形状 | 色 | 文案 | 课时结算 |
|---|---|---|---|---|---|
| **出勤** `present` | `check` | 实心圆 ● | `--success` | `出勤` | `−1 节` |
| **迟到** `late` | `clock` | 半填充圆 ◐ | `--warn` | `迟到 8 分` | `−1 节` |
| **请假·提前≥24h** `leave_approved` | `calendar-x` | 空心圆 ○ | 中性 `--neutral-fg` | `请假·已准` | **`不扣`** |
| **请假·不足24h** `leave_late` | `calendar-clock` | 圈中斜杠 ⊘ | `--warn` | `请假·照扣` | **`−1 节`** |
| **旷课** `absent` | `x` | 叉 ╳ | `--danger` | `旷课` | `−1 节` |
| **未记录** `unrecorded` | `circle-dashed` | 虚线圈 ⬚ | `--meta` | **`未记录`** | `待确认` |

**关于请假的两条硬规则（与服务端契约一致，见 openapi.yaml §请假）：**

- **`leave_approved` / `leave_late` 由服务端在提交瞬间按 `(lesson.start − now) ≥ 24h` 判定，没有 admin 审批环节，老师也无权修改。** UI 必须把它渲染成**已完成的结论**，绝不能渲染成「待处理 / 待批」——那会凭空造出一个服务端不存在的中间态。老师可提交的只有 `present / late / absent` 三态。
- 两者**同属「请假」但结算相反**（不扣 / 照扣），所以形状必须区分：`○` 空心 vs `⊘` 圈中斜杠。`leave_late` 用 `--warn` **而非 `--danger`** —— 它是"已登记但要付费"，不是错误，也不是流失；`⊘` 与迟到的 `◐`（斜杠 vs 半填充）在灰度下完全可分。

**三条硬性要求：**

1. **「未记录」必须是显式状态，不能是空白单元格。** 老师扫读点名表时，空白会误读为"这节课没这个人"。未记录用虚线圈 ⬚ + 灰占位文字，且**可点击就地填写**（点一下弹出 `出勤 / 迟到 / 旷课` 三选项的分段控件）。
2. **每个出勤状态旁必须显示「课时结算结果」**（`−1 节` / `不扣`）。这是把"课时是钱"落到界面的关键 —— 老师点完名就知道谁的钱动了，家长在 `我的课时` 里看到的是同一行同一个字。
3. **请假两态刻意不用绿色也不用红色** —— 它不是成功也不是失败，是"冻结 / 半冻结"。中性 + 空心圆 = 不扣，`--warn` + 圈中斜杠 = 照扣；**靠形状而非仅靠颜色区分**。

灰度验收：实心 ● / 半填 ◐ / 空心 ○ / 圈中斜杠 ⊘ / 叉 ╳ / 虚线 ⬚ —— 六种形状在灰度下两两可辨。

### 4.3 跟进逾期（时间驱动 → 倒计时文本承担语义）

48h SLA。表达方式：**不是"红色 badge"，而是「相对时间文案 + SLA 进度条」**。

- 文案即语义：`还有 6 小时`（中性）· `超期 3 小时`（`--warn`）· `超期 2 天`（`--danger` + `circle-alert` 图标）
- SLA 条：宽 72px 高 4px，轨道 `--sla-track`；**24h 处有一道竖刻度线**；越过 48h 时条整体 `--danger` 且左端溢出 1px 显示。
- **排序强制**：该列表永远按"超期时长倒序"，视觉严重度与信息优先级一致，不给用户自己排。
- 逾期行的**行内动作**是具体的沟通方式（`打电话` / `发微信` / `标记已跟进`），不是一个泛用"处理"。

### 4.4 试听结果（二维，不能压成一维）

最常见的设计错误：把「试听结果」和「是否已跟进」合并成一个颜色。**必须拆成两个独立的列/徽记**，因为"结果好但没跟进"恰恰是 admin 最危险的状态。

| 维度 A：试听结果 | 形状 | 色 | 文案 |
|---|---|---|---|
| 待反馈 | 虚线圈 + `circle-dashed` | 中性虚线 | `待反馈` |
| 已报名 | 实心圆 + `check` | `--success` | `已报名` |
| 观望 | 半填充圆 + `clock` | `--warn` | `观望` |
| 未报名 | 斜杠圆 + `circle-slash` | **中性**（不用红色） | `未报名` |

> 未报名 ≠ 错误。流失是经营常态，用红色会污染 semantics 并让列表变成"全是红的"。用中性 + 形状。

| 维度 B：跟进状态 | 图标 | 色 | 文案 |
|---|---|---|---|
| 未跟进 | `circle-dashed` | 中性 | `未跟进` |
| 48h 内 | `clock` | `--warn` | `今日需跟进` |
| 超期 | `circle-alert` | `--danger` | `超期 2 天` |
| 已跟进 | `check` | `--success` | `8/17 电话已记` |

### 4.5 LLM 建议可用 vs 不可用（降级态）

**设计目标：LLM 失败时，用户的工作量一点都不增加。**

布局位置、高度、可操作按钮与「可用态」完全一致 —— 只有**容器、图标、标题、依据来源**改变，**没有 displacement、没有 spinner 闪烁、没有"请重试"把失败丢给用户**。

| 维度 | 可用态 | 降级态 |
|---|---|---|
| 容器 | `1px var(--accent)` 描边 + `--surface-warm` 底 | `1px dashed var(--border-strong)` + `--surface` 底 |
| 图标 | `sparkles` 16px | `list-checks` 16px |
| 标题 | `AI 建议 · 转化可能性高` | `按规则判断 · 转化可能性高` |
| 置信度 | `高 · 0.82` 胶囊 | 不显示（规则态无置信度） |
| 依据 | AI 生成 3 条理由 | **同一批 evidence 字段**，由确定性规则渲染（如：试听反馈含"再考虑" + 未在 48h 内跟进 + 同龄学生转化率 61%） |
| 脚注 | `基于 8 条记录 · 8/19 10:12 生成` | `AI 建议暂不可用，已按规则给出结论` + Ghost `重试生成` |
| 动作按钮 | `[ 安排试听 ]` `[ 标记观望 ]` | **完全相同**，位置不动 |

**两条必须区分的失败：**

1. **structured output 校验失败 / 超时** → 服务端已静默重试 1 次仍失败 → 直接渲染降级卡片，**不给重试按钮**（用户不该为后端的事点按钮）。
2. **LLM 不可达 / 未配置** → 渲染降级卡片 + Ghost `重试生成`（这是环境性问题，用户可以自己决定要不要再试一次）。

灰度验收：可用态与降级态的颜色都在中性/强调范围内，靠**图标（sparkles vs list-checks）+ 标题文本 + 实线 vs 虚线边框**区分 —— 天然色盲安全。

## 5. 图标系统（已锁定）

### 5.1 锁定结论

> **Lucide Icons** — lucide.dev / npm `lucide-react`（React 官方适配包，tree-shakable，MIT）

**选型理由：**
1. 统一 `stroke-width: 2`、统一 `24×24` viewBox —— 缩放到 16/20/24 时视觉重量一致，不会像混合图标集那样粗细打架。
2. 语义库齐备（1490+ 图标），本项目需要的全部付薪achen语义都有对应的一级 icon，不需要拿近似图标凑数。
3. 官方 React 包 `lucide-react`，与已锁定的 **Vite + React + TypeScript** 零摩擦，`import { BellRing } from 'lucide-react'`，size / strokeWidth / aria-label 全部可 props 化。
4. MIT、社区 fork 自 Feather，长期维护，不像商务图标库那样部分图标要走付费授权。

**备用做法（不启用）：** Tabler Icons。**全项目只用一套 → Lucide。** 禁止混用第二套。

### 5.2 尺寸规范

| 场景 | 尺寸 | stroke |
|---|---|---|
| 行内 / 表格 / badge 内 | **16px** | 2（缩到 16 建议在 volumetric 上保持 2，不加粗） |
| 按钮内（图标 + 文字 / 纯图标按钮） | **20px** | 2 |
| 独立图标、空状态插画、导航折叠态 | **24px** | 1.75（24px 时用 1.75 更接近视觉体重） |

> **零 emoji。** P0 规则。全项目扫描正则 `[\x{1F300}-\x{1F9FF}\x{2600}-\x{26FF}\x{2700}-\x{27BF}]` 必须零命中。emoji 仅允许出现在家长填写的请假理由里（UGC），不得作为 UI 图标。

### 6.1 页面数：6 个（克制）

| # | 路由 | 页面名 | 主要角色 | 为什么独立成页 |

| 1 | `/today` | **工作台** | admin | admin 默认首屏。今天该做什么，全部可就地处理 |
| 2 | `/leads` · `/leads/:id` | **线索与试听** | admin | 含 LLM 转化决策卡。列表 + 抽屉/详情页 |

### 6.2 每个角色登录后的第一屏

| 角色 | 默认落地页 | 第一屏看到的三件事 | 最高频动作的步数 |
|---|---|---|---|
| **admin** | `/today` | ① 跟进超期 3 条（名/事由/超期多久）② 今日/明日试听 4 节 ③ 低课时预警 6 人 | 催续费 = **1 步**（行尾直接点）；记跟进 = **1 步**（抽屉内填，不跳页） |
| **teacher** | `/teach/today` | ① 现在/下一节是什么课、几分钟后 ② 该班的**新生**有几人、请假几人 ③ 昨天的课是否已点名 | 点名 = **2 步**（今日课表 → 班级）；快速改单个状态 = **1 步**（列表 inline 分段控件） |

### 6.3 权限在 UI 上的体现（不能只在后端）

- admin 看到"全部学生"但**只能写自己归属的**：非自己学生的行，动作按钮渲染为 `disabled` + `tooltip: 归属顾问 Mei Lin，仅可查看`。**不是隐藏** —— 隐藏会让"能看不能改"变成 bug。
- teacher 侧栏只有 `今日课堂` / `我的班级` 两项，看不到"线索""结算"。
- 家长端顶部无侧栏，只有 `我的课时` / `请假` / `通知` 三个 tab。

## 9. 响应式与无障碍

**响应式**（根 mobile-first 但主战场是桌面，iPad 是次要场景）
- `<768px`：侧栏 → 顶栏汉堡抽屉；表格 → **卡片列表**（每行变一张卡，状态徽记放大）；**出勤状态变 44×44px 分段按钮**（老师用 iPad 点名）；你会/re geht `(41, no)`。
- `768–1279px`：侧栏折叠到 64px 图标栏；表格首列 sticky，其余横向滚动。
- `≥1280px`：完整布局。
- 家长端 `/me` **移动优先**单列，按钮 ≥44×44px。

**无障碍**（P0，实现时由 `/audit` 专项检查）
- 状态全部三通道编码，禁用纯色区分（本项目一票否决项，见 §4.0）
- 文本对比度：正文 ≥4.5:1，`--meta` 仅限图标/disabled，不得用于正文
- 键盘：表格可 Tab 遍历、粒度态可用 `Enter` 打开 + `←/→` 切换 + `Enter` 提交 + `Esc` 取消；⌘K 全局搜索；`/` 聚焦筛选
- 焦点环统一 `var(--focus-ring)`：`0 0 0 2px #FFF, 0 0 0 4px rgba(15,92,115,.45)`
- 所有纯图标按钮必须 `aria-label`；表格 `aria-sort`；Toast 用 `role="status"`，错误用 `role="alert"`
- `prefers-reduced-motion: reduce` → 关闭全部 transition（本项目 Motion=2，本就极少）

## 10. Do's & Don'ts

**应该**
1. 每行都朝「今天要做什么」收敛，行尾给**具体动作**（打电话 / 催续费 / 点名），不给通用的「查看 / 编辑」
2. 状态永远 颜色 + 形状 + 文本 三通道
3. 课时用 `剩余 / 总量` 绝对数字 + 条 + 预计用尽日期
4. 「未记录」显式占位，可就地填写
5. 每个出勤状态旁边写明课时结算结果（`−1 节` / `不扣`）
6. LLM 降级时位置、高度、动作按钮完全不变
7. 金额 / 课时 / 时间 / 学号一律 `tabular-nums`

**不应该**
1. 任何形式的 emoji 作为功能图标（本项目 UI 一票否决项；已用 emoji 正则扫描，全文零命中）
2. 任何渐变、发光边框、毛玻璃（本项目 Motion=2 / Variance=3，全部不需要）
3. 超过 **8px** 的圆角、装饰性阴影、`1px border + blur≥16` 同时出现（幽灵卡片）
4. 「 Welcome to 」「 Lorem ipsum 」「 暂无数据 」「 加载中... 」这类空洞文案 —— 所有文案必须是这个业务里真实会出现的话
5. 把每张表做成一个 CRUD 页面
6. 只用彩色圆点表示状态
7. 请假/流失用红色（它们是经营常态，不是错误）
8. 隐藏"能看不能改"的数据 —— 置灰 + tooltip 说明归属顾问
9. 给 UI 上色却解决不了问题：≤5 节课时的正确答案是**出现一个按钮**，不是把数字染得更红
10. ALL CAPS 标题不带 `letter-spacing ≥ 0.06em`

## 附录 C · 交接给前端的实现要点

0. **组件库决策（已定，勿改）：Tailwind v4.3.3 + 自建 8 个组件，不引入 AntD、不引入 Radix / shadcn/ui。**
   无障碍由我们自己的实现保证（见 §9：focus ring、aria-sort、aria-label、role=alert、≥44px 触摸目标、reduced-motion），不依赖第三方 a11y 基底。**本文档的 Tokens 全部保留、一个值都不改** —— Tokens 是设计资产，与组件库选型无关，前端直接按 Tokens 自建组件。
1. **实现方式**：Tailwind config 里把 `docs/UIUX.md §3.2` 与 `附录 A/B` 的 Token 全部映射为 `theme.extend`（colors / fontFamily / fontSize / spacing / borderRadius / boxShadow / borderWidth），组件内**禁止出现裸 hex**。
2. **表格组件统一**：不能用三套表格实现。列宽策略：`auto / 1fr / auto`，数字列 `tabular-nums` 右对齐。
3. **三种状态组件必须做成受控组件并禁止散写**：`<CreditCell>` `<AttendanceBadge>` `<StatusBadge variant="...">`。这是本次"状态一眼能区分"能否落地的关键 —— 只要有一处手写了 `<span style="color:#...">`，这条就废了。
4. **LLM 卡两个组件共用同一套 props**：`<DecisionCard mode="ai"|"rule" evidence={[]} actions={[]} />`，由同一个 hook 根据服务端响应 `source` 字段切换。**不要写成两个布局。**
5. **课时数字渲染统一走 `.num` class**（`font-variant-numeric: tabular-nums` + mono）。
6. Phase 3 实现完成后走 `/audit` 专项检查：对比度、键盘路径、CVD 灰度、emoji 扫描。
